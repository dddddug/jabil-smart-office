二、全局架构与开发约束（⚠️ 核心补充）
2.1 数据库建设策略
⚠️ 强制约束：当前数据库 stockroom_db 中不存在本项目所需的任何业务表。 - 全量新建：所有模块（用户、排班、工位、单据、KPI等）对应的数据表均需从零创建。 - 禁止复用：严禁假设或依赖任何已有表结构，必须先执行完整的 DDL 建表脚本。 - 初始化数据：建表后需同步提供基础字典数据、角色权限、系统配置等种子数据插入脚本。

2.1.1 数据库表命名规范
⚠️ 强制约束：所有数据库表必须遵循以下命名规范，避免与数据库中已有表冲突。

命名格式：jso_系统模块_功能表名

命名说明：
- jso：Jabil Smart Office 系统前缀，统一标识本系统的表
- 系统模块：表所属的功能模块分类，如 system（系统管理）、org（组织结构）、biz（业务）等
- 功能表名：具体功能的表名，清晰描述表的用途

模块分类示例：
- system：系统管理模块（用户、角色、权限、配置等）
- org：组织结构模块（厂区、部门、员工等）
- biz：业务模块（排班、工位、单据等）
- report：报表模块（KPI、Cost汇总等）

命名示例：
- jso_system_role_management：系统管理 - 角色管理表
- jso_system_user_management：系统管理 - 用户管理表
- jso_org_plant_management：组织结构 - 厂区管理表
- jso_org_department_management：组织结构 - 部门管理表
- jso_org_employee_roster：组织结构 - 员工花名册表
- jso_biz_employee_schedule：业务 - 员工排班表
- jso_biz_station_arrangement：业务 - 工位安排表

索引命名规范：idx_表名_字段名
示例：idx_jso_system_role_management_status

序列命名规范：表名_id_seq
示例：jso_system_role_management_id_seq

字段命名规范：使用下划线命名法（snake_case）
示例：id, name, description, status, created_at, updated_at
2.2 Trae 开发环境约束
⚠️ 强制约束：使用 Trae 进行开发时，拒绝安装任何额外程序/插件/扩展。 - 仅使用 Trae 原生内置功能及项目已有依赖。 - 不得通过 Trae 市场安装第三方工具、LSP、格式化插件等。 - 所有开发、调试、构建操作必须在纯原生环境下完成。
2.3 开发顺序策略
⚠️ 强制约束：严格遵循 “前端优先 → 微信端跟进 → 后端补齐” 的开发节奏。 1. 第一阶段（前端）：完成 PC/平板/手机网页端全部页面、交互、Mock 数据对接。 2. 第二阶段（微信端）：基于已定稿的前端 UI 与接口契约，开发微信小程序端。 3. 第三阶段（后端）：根据前端 + 微信端实际调用的接口清单，反向补齐后端 API、业务逻辑与数据库实现。 - 后端开发以前端/微信端已确认的接口文档为唯一依据，禁止提前过度设计。

5.5.2 核心计算逻辑
福利费用：
plain
福利费用 = (福利基数 × 当月3PL在职人数) / 当月天数

plain
工时费用 = Σ(员工当日工时 × 当日生效费率)
Gap（结余）：
plain
Gap = 预算总计 - 实际费用

8.1 业务月（财务月）周期定义
⚠️ 强制规范：系统内所有"月份"维度严禁使用自然月
表格
项目	定义
起止时间	每月24日 00:00:00 至 次月23日 23:59:59
归属逻辑	周期归属为"起始日所在的自然月"
示例	2026-06-24 00:00 ~ 2026-07-23 23:59 → "2026年6月（June 2026）"
技术落地：
sql
CREATE OR REPLACE FUNCTION get_business_month(ts TIMESTAMP)
RETURNS VARCHAR(7) AS $$
DECLARE
    start_date DATE;
BEGIN
    start_date := DATE_TRUNC('month', ts) + INTERVAL '23 days';
    IF ts >= start_date THEN
        RETURN TO_CHAR(ts, 'YYYY-MM');
    ELSE
        RETURN TO_CHAR(ts - INTERVAL '1 month', 'YYYY-MM');
    END IF;
END;
$$ LANGUAGE plpgsql;
前端交互： 月份选择器必须显示 2026年6月 (06/24 - 07/23)

    BEFORE UPDATE ON jso_config_dept_calc_rules

-- ========================================
-- 更新时间触发器函数（通用）
-- ========================================
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

14.10 自动停用用户机制
功能：每天凌晨1点自动检查并停用离职超过1个月的用户
触发方式：
- 服务器启动时立即执行一次
- Cron 定时任务：每天 01:00 执行
逻辑：
- 计算离职日期的次月第一天
- 如果今天 >= 次月第一天，则自动将用户和员工花名册状态设为 inactive
